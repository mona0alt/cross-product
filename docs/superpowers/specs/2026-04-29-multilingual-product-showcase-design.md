# 多语言商品展示与智能后台管理系统设计文档

## 1. 背景与第一阶段目标

本项目第一阶段聚焦于构建一个可上线的多语言商品展示站点，以及一个供单管理员使用的后台管理系统。目标是在尽量控制复杂度的前提下，完成商品展示、分类浏览、商品详情、多语言切换、留言与订阅、后台商品管理与审核发布等核心能力。

第一阶段明确纳入范围的能力如下：

- 前台多语言商品商城
- 单管理员后台登录与管理
- 商品、分类、Banner 的创建、编辑、审核与发布
- 四语内容录入与展示：`zh-CN`、`en`、`es`、`pt`
- 前台统一展示 `USD` 价格
- 留言表单提交，后台查看留言并标记已处理
- 邮箱订阅提交，后台查看订阅列表
- WhatsApp Business 客服跳转入口

第一阶段明确不纳入范围的能力如下：

- 外部网站商品抓取
- 自动上新与审核流水线
- 订阅邮件自动发送
- AI 行为分析与报表
- 会员体系、订单系统、购物车与支付
- 多角色权限系统

## 2. 技术方案

### 2.1 选型

采用 `Next.js + PostgreSQL` 的单体应用方案。

原因：

- 当前仓库为空，单体方案更适合从 0 到 1 快速搭建
- 前台、后台、API、鉴权共用一套类型与数据模型，开发效率更高
- Next.js 天然适合商品展示站点、SEO 与多语言路由组织
- 第一阶段复杂度可控，后续仍可以把抓取、邮件、分析拆成独立服务

### 2.2 系统边界

系统按以下 4 个层面组织：

1. 前台商城
2. 后台管理
3. 服务端 API
4. PostgreSQL 数据库

职责划分如下：

- 前台商城只读取已发布的数据，用于展示和用户交互
- 后台管理负责录入、编辑、审核、发布与内容维护
- 服务端 API 统一负责权限校验、数据校验、表单处理与查询
- PostgreSQL 作为唯一主数据源，存储商品、分类、Banner、留言、订阅等数据

## 3. 第一阶段信息架构

### 3.1 前台页面

- `/`
  - 首页
- `/products`
  - 商品列表页，支持搜索、分类筛选、过滤器
- `/products/[slug]`
  - 商品详情页
- `/categories/[slug]`
  - 分类落地页
- `/contact`
  - 留言页
- `/subscribe`
  - 订阅入口页，可选；也可以在首页/页脚放轻量订阅表单
- `/portal`
  - 客户端入口页，第一阶段作为轻量入口或占位页

### 3.2 后台页面

- `/admin/login`
  - 管理员登录页
- `/admin`
  - 后台首页/概览页
- `/admin/products`
  - 商品列表页
- `/admin/products/new`
  - 新建商品页
- `/admin/products/[id]`
  - 商品编辑与发布页
- `/admin/categories`
  - 分类管理页
- `/admin/banners`
  - Banner 管理页
- `/admin/messages`
  - 留言管理页
- `/admin/subscribers`
  - 订阅邮箱列表页

## 4. 前台功能设计

### 4.1 顶部区域

顶部区域包含：

- Logo
- 搜索框
- 语言切换器
- 客户端入口
- WhatsApp 客服按钮

语言切换器支持：

- `zh-CN`
- `en`
- `es`
- `pt`

切换后需要同步变化的内容包括：

- 所有静态文案
- 分类名称与描述
- 商品名称、简介、详情
- 按钮提示与表单提示

### 4.2 首页

首页按以下顺序组织：

1. 顶部区域
2. Banner 轮播图
3. 一级分类导航
4. 分类图标区
5. 推荐商品区
6. 订阅入口

Banner 要支持后台配置：

- 图片
- 排序
- 启用/停用
- 跳转目标

Banner 跳转目标第一阶段支持：

- 分类页
- 商品详情页
- 外部链接

### 4.3 分类导航与商品列表

分类结构为一级分类与二级分类。

首页可展示一级分类导航；进入分类或商品列表页后展示二级分类过滤。分类图标支持点击后进入对应商品列表。

商品列表页支持：

- 关键词搜索
- 一级分类筛选
- 二级分类筛选
- 过滤器占位

第一阶段过滤器建议保持克制，优先支持：

- 是否推荐
- 分类条件
- 关键词检索

如需价格区间过滤，可作为可选项保留实现空间，但不建议在第一阶段做复杂价格筛选体验。

### 4.4 商品详情页

商品详情页必须包含：

- 主图
- 缩略图库
- 大图查看功能
- 商品名称
- 商品编码
- 商品简介
- `USD` 价格
- 商品详情描述
- 推荐商品区块
- 留言/咨询入口

详情页是主要转化页，应确保图片优先、价格清晰、文案结构明确。

### 4.5 留言与订阅

留言表单字段固定为：

- 姓名
- 邮箱
- 留言内容

提交成功后前台给出明确反馈。

订阅功能支持用户录入邮箱并提交，数据入库后后台可查看订阅列表。第一阶段不做退订流程与自动邮件通知。

### 4.6 客服跳转

点击客服按钮后，前台直接打开预先绑定的 WhatsApp Business 对话链接。链接中的目标账号在后台配置或环境变量中维护。

## 5. 后台功能设计

### 5.1 鉴权模型

后台采用单管理员模型。

- 仅一个管理员账号登录后台
- 登录后拥有全部后台管理权限
- 暂不实现多角色和细粒度权限控制
- 数据模型保留未来扩展空间，但第一阶段不提前实现

### 5.2 商品管理

商品列表需要支持：

- 按状态筛选：`draft`、`pending`、`published`、`archived`
- 按分类筛选
- 按商品编码搜索
- 按商品名称搜索

商品编辑页分为以下区域：

- 基础信息
  - 商品编码
  - 价格
  - 封面图
  - 分类
  - 推荐标记
- 多语言内容
  - `zh-CN` 名称、简介、详情
  - `en` 名称、简介、详情
  - `es` 名称、简介、详情
  - `pt` 名称、简介、详情
- 图片管理
  - 封面图
  - 详情图/图库
- 发布控制
  - 保存草稿
  - 提交待审核
  - 直接发布
  - 下架/归档

虽然第一阶段只有单管理员，但保留 `pending` 状态有利于第二阶段接入自动抓取后的人工审核流程。

### 5.3 分类管理

分类管理支持：

- 创建一级分类
- 在一级分类下创建二级分类
- 编辑分类
- 调整排序
- 启用/停用

分类字段需维护：

- 四语名称
- 四语描述
- slug
- 图标
- 排序值
- 启用状态

### 5.4 Banner 管理

Banner 管理支持：

- 上传 Banner 图片
- 设置跳转目标
- 排序
- 启用/停用

这样首页轮播位的运营调整无需改代码。

### 5.5 留言管理

留言列表展示以下内容：

- 姓名
- 邮箱
- 留言摘要
- 提交时间
- 处理状态

后台支持：

- 查看留言详情
- 标记已处理

第一阶段不实现后台回复或工单流。

### 5.6 订阅管理

后台支持查看订阅邮箱列表，包括：

- 邮箱
- 状态
- 创建时间

第一阶段不做邮件发送与营销活动管理。

## 6. 数据库设计

第一阶段采用固定四语字段平铺模式，不拆分为翻译子表。原因是语言集合固定，平铺字段实现更直接，后台录入和前台查询成本更低，更适合当前 MVP。

### 6.1 `admins`

用途：存储后台管理员账号。

字段建议：

- `id`
- `username`
- `password_hash`
- `created_at`
- `updated_at`

### 6.2 `categories`

用途：存储一级与二级分类。

字段建议：

- `id`
- `parent_id`
- `slug`
- `sort_order`
- `icon_image_url`
- `is_active`
- `name_zh`
- `name_en`
- `name_es`
- `name_pt`
- `description_zh`
- `description_en`
- `description_es`
- `description_pt`
- `created_at`
- `updated_at`

说明：

- `parent_id` 为空表示一级分类
- `parent_id` 非空表示其下挂载的二级分类

### 6.3 `products`

用途：存储商品主信息。

字段建议：

- `id`
- `category_id`
- `slug`
- `product_code`
- `price_usd`
- `cover_image_url`
- `status`
- `is_recommended`
- `sort_order`
- `published_at`
- `created_at`
- `updated_at`
- `name_zh`
- `name_en`
- `name_es`
- `name_pt`
- `intro_zh`
- `intro_en`
- `intro_es`
- `intro_pt`
- `detail_zh`
- `detail_en`
- `detail_es`
- `detail_pt`

状态建议：

- `draft`
- `pending`
- `published`
- `archived`

### 6.4 `product_images`

用途：存储商品图库，用于详情页缩略图与大图查看。

字段建议：

- `id`
- `product_id`
- `image_url`
- `alt_text`
- `sort_order`
- `created_at`

### 6.5 `banners`

用途：存储首页轮播图。

字段建议：

- `id`
- `image_url`
- `target_type`
- `target_id`
- `target_url`
- `sort_order`
- `is_active`
- `created_at`
- `updated_at`

`target_type` 建议支持：

- `category`
- `product`
- `url`

### 6.6 `messages`

用途：存储前台留言数据。

字段建议：

- `id`
- `name`
- `email`
- `content`
- `status`
- `created_at`
- `processed_at`

状态建议：

- `new`
- `processed`

### 6.7 `subscribers`

用途：存储订阅邮箱。

字段建议：

- `id`
- `email`
- `status`
- `created_at`

状态建议：

- `active`
- `unsubscribed`

## 7. 核心业务规则

### 7.1 唯一性规则

- `products.slug` 唯一
- `products.product_code` 唯一
- `categories.slug` 唯一
- `subscribers.email` 建议唯一

### 7.2 发布规则

商品允许发布的前提：

- 已选择分类
- 已填写商品编码
- 已填写 `price_usd`
- 已上传封面图
- 四种语言的名称、简介、详情全部完整
- slug 唯一且合法

分类允许启用的前提：

- 四种语言名称完整
- slug 唯一

Banner 允许启用的前提：

- 图片存在
- 跳转目标有效

### 7.3 前台可见性规则

- 只有 `published` 状态商品对前台可见
- 只有 `is_active = true` 的分类对前台可见
- 只有 `is_active = true` 的 Banner 参与首页轮播
- 推荐商品必须同时满足已发布条件

## 8. 错误处理策略

### 8.1 前台

- 商品不存在或已下架：返回 `404` 或商品不可用提示
- 分类不存在：返回 `404`
- 搜索无结果：展示空状态
- 留言或订阅提交失败：展示明确错误提示

### 8.2 后台

- 未登录访问后台：跳转到 `/admin/login`
- 商品编码重复：阻止保存
- slug 冲突：阻止保存
- 发布资料不完整：阻止发布，并指明缺失字段
- 分类被商品引用时：不允许直接删除，改为停用
- Banner 跳转目标失效：阻止启用或保存

## 9. 测试策略

### 9.1 单元测试

优先覆盖以下逻辑：

- 商品发布校验规则
- 多语言字段完整性校验
- slug 唯一性相关逻辑
- 商品编码唯一性相关逻辑
- 留言表单校验
- 订阅邮箱表单校验

### 9.2 集成测试

优先覆盖以下服务端接口：

- 管理员登录
- 商品创建
- 商品编辑
- 商品发布
- 分类创建/编辑
- Banner 创建/编辑
- 留言提交
- 留言标记已处理
- 订阅提交

### 9.3 页面级验证

至少验证以下关键页面能够正常渲染并完成主要交互：

- 首页
- 商品列表页
- 商品详情页
- 后台商品列表页
- 后台商品编辑页
- 后台留言列表页

### 9.4 人工验收清单

- 语言切换后页面文案与商品字段是否完整
- Banner 是否跳转到正确目标
- 分类图标是否进入对应商品列表
- 商品详情页大图预览是否可用
- 留言与订阅是否成功入库
- 后台留言处理状态是否可更新

## 10. 第二阶段预留扩展

为后续功能预留的扩展方向：

- 商品抓取来源配置
- 自动抓取与去重
- 商品抓取后进入待审核状态
- 新品自动通知订阅用户
- 前台埋点与用户行为收集
- 热门商品/分类排行
- 跳出率与转化路径分析
- AI 建议与推荐位优化

第一阶段不实现这些能力，但数据库结构与商品状态设计需要避免阻碍后续扩展。

## 11. 结论

第一阶段采用 `Next.js + PostgreSQL` 的单体实现路线，先上线一个可维护、可发布、可多语言切换的商品展示系统，并配套单管理员后台。该方案能满足当前业务展示与内容运营需求，同时为第二阶段的抓取、通知、分析能力保留清晰扩展路径。
