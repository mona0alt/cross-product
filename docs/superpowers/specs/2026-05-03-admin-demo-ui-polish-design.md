# 后台 Demo UI 统一化与美化设计文档

## 1. 背景

当前项目的后台管理页面已经具备基本的 demo 信息架构，能够表达商品中心、抓取任务、订阅与通知、AI 数据分析、分类管理、横幅管理、留言管理等模块。

但现阶段存在以下问题：

- 各页面顶部元素呈分裂状态，全局头部、页级标题、操作区之间缺少统一结构
- 页面之间的左边线、卡片节奏、留白和模块层级不一致
- 核心页面虽然有内容，但首屏缺少稳定的信息组织，不利于给用户做静态确认
- 表格、卡片、表单、状态标签的视觉语言还不够统一，页面看起来像多个独立页面拼接

本轮目标不是实现真实后台能力，而是先把后台 demo 做成一套更完整、更专业、更适合拿给用户做静态确认的高保真前端原型。

用户已确认的约束如下：

- 本次只做需求确认阶段的后台 demo
- 保留当前整体暖色调和已有品牌感，不推翻现有风格
- 优先解决顶部割裂、展示不对齐、页面不成体系的问题
- 覆盖全部核心后台页面，而不是只修个别页面
- 允许进行中度重构，但不改业务信息架构和真实功能边界

## 2. 设计目标

本次 UI 美化的目标为：

- 让所有后台页面看起来属于同一套产品
- 统一后台壳层、页头、首屏和内容节奏
- 突出商品工作流、抓取、通知、分析这四个核心 demo 页面
- 在不引入真实业务逻辑的前提下，提升后台的可信度和演示完成度

成功标准如下：

- 用户进入任一 admin 页面，都能看到一致的顶部结构和页面层级
- 核心页面首屏具有清晰的信息重点，而不是松散堆叠
- 表格、表单、卡片、状态标签的风格统一
- 页面整体更适合用于客户需求确认，而非仅供内部开发占位

## 3. 设计结论

本次采用的方案为：

- 保留当前 admin 暖色调、衬线标题和浅底卡片的整体方向
- 不重新设计后台信息架构，而是在现有页面上统一壳层和页面首屏
- 对核心页面采用“强首屏”，对配置和支撑页面采用“轻首屏”
- 通过公共组件收口页面风格，而不是对每个页面做互相独立的美化

不采用的方案包括：

- 只做细节修饰，不调整壳层和页头结构
- 直接把后台做成强 BI 驾驶舱风格
- 为了演示效果过度增加插画、装饰和复杂视觉模块

原因：

- 只做轻修饰无法解决页面割裂问题
- 驾驶舱风格会弱化后台工作流和操作路径
- 过度设计会削弱后台 demo 的可信度，偏离用户确认需求的目标

## 4. 整体视觉方向

### 4.1 视觉气质

后台保持“稳重、温和、有品牌感”的 B2B 管理后台气质：

- 浅暖色背景
- 白色或浅色卡片
- 深色正文与标题
- 管理操作使用有限强调色
- 状态颜色克制但足够清晰

视觉表达重点不是追求强烈冲击，而是强调：

- 清楚
- 成体系
- 接近正式后台

### 4.2 统一原则

所有后台页面统一遵循以下原则：

- 页面顶部结构统一
- 主内容容器宽度和边距统一
- 卡片圆角、边框、内边距统一
- 标题层级统一
- 操作按钮高度、样式和分组逻辑统一
- 状态标签语义统一

## 5. 后台壳层设计

### 5.1 左侧导航

左侧导航继续沿用当前固定侧栏模式，但优化为更完整的后台壳层组成部分。

调整原则：

- 保留后台标题区和版本区
- 当前激活项视觉更稳定，避免只靠轻色块表达
- 导航项图标、文字、badge 的对齐更精确
- 顶部品牌区、主导航区、底部版本区之间形成清晰分段

预期效果：

- 左侧导航既保留现有品牌感，又更像正式后台导航系统

### 5.2 全局头部

全局头部不再只是一个独立工具条，而是后台所有页面共用的顶层信息带。

统一结构如下：

- 左侧：后台定位文案和当前系统说明
- 右侧：管理员信息卡与退出操作

调整原则：

- 头部背景、边框、透明度与主内容建立连续关系
- 不在全局头部放页面级操作，避免与页级标题区职责混乱
- 让全局头部承担“系统级身份与上下文”职责

### 5.3 主内容区

主内容区统一为固定左边线与稳定宽度的内容容器。

统一规则：

- 所有 admin 页面共用一致的左右 padding
- 页面首屏与后续内容模块共享同一基线
- 页面模块间距统一，不再按页面各自定义

这一步是解决“展示不对齐”的关键。

## 6. 页级标题与首屏结构

### 6.1 页级标题区

所有后台页统一使用同一个页级标题结构：

- label
- title
- description
- action

页级标题区的职责是说明当前模块的任务和入口，而不是承载所有内容。

统一规则：

- 标题层级一致
- 描述文字宽度一致
- 操作按钮排列一致
- 页级标题和内容首屏属于同一视觉组

### 6.2 强首屏与轻首屏

本轮将页面分为两类：

- 强首屏页面：商品中心、抓取任务、订阅与通知、AI 数据分析
- 轻首屏页面：分类管理、横幅管理、留言管理、新建商品、编辑商品

强首屏页面在标题区下方补统一的摘要信息区，用于建立页面重点和演示氛围。

轻首屏页面只保留统一标题区和标准内容容器，不额外堆叠过多摘要卡，避免页面过重。

## 7. 核心页面首屏策略

### 7.1 商品中心

商品中心是后台 demo 的核心页面，首屏采用“标题区 + 摘要卡 + 主操作”结构。

页面首屏应重点表达：

- 商品池规模
- 当前待审核压力
- 今日新增候选量
- 两个最重要入口：发起抓取、新建商品

首屏之后再进入：

- 来源和状态筛选
- 商品表格
- 审核详情侧栏

页面目标是让用户一眼理解“所有商品统一进入一个工作流”。

### 7.2 抓取任务

抓取任务页首屏应强调“这是候选商品入口页，不是最终商品列表”。

页面首屏建议表达：

- 今日抓取摘要
- 来源站点健康状态
- 抓取成功后进入审核池的流程说明

第二层内容再展示来源站点状态卡和异常说明。

### 7.3 订阅与通知

订阅与通知页首屏应更像运营通知面板。

页面首屏重点：

- 订阅用户总数
- 新品通知打开率
- 待发送活动
- 失败重发数量

首屏之后承接：

- 活动列表
- 失败队列
- 订阅用户区块

即使当前仍以 mock 数据展示，也要让用户能直观理解发布与通知的关系。

### 7.4 AI 数据分析

AI 数据分析页首屏采用“本周结论 + 洞察摘要”的方式。

页面首屏重点：

- 一句本周经营结论
- 若干洞察卡片
- 一个明确的“已生成”状态标识

后续内容按信息层级分区为：

- 热门商品/分类
- 用户转化路径
- 高跳出页面
- 推荐位或选品建议

目标不是做真实 BI，而是做可执行建议的展示型分析页。

## 8. 组件级统一规范

### 8.1 标题系统

后台统一只保留两级主要标题系统：

- 全局头部标题
- 页面标题区标题

页面内部区块标题统一降级为卡片标题体系，不再每个页面单独定义大标题风格。

### 8.2 摘要卡

摘要卡统一为标准结构：

- 顶部小标签
- 中间主数值或主结论
- 底部补充说明

统一规则：

- 高度统一
- 圆角统一
- 边框与底色统一
- 数值字号统一
- 图标与文字对齐统一

### 8.3 表格容器

表格统一使用同一种外层容器和内部节奏。

统一规则：

- 表格外层统一卡片容器
- 表头字体和字距统一
- 行高统一
- hover 态统一
- 空状态与说明文字样式统一

适用页面：

- 商品中心
- 留言管理
- 横幅管理
- 订阅用户列表

### 8.4 筛选条与操作栏

列表页的筛选项和主操作统一为同一条顶部操作带。

结构原则：

- 左侧放筛选和状态切换
- 右侧放主操作按钮

避免出现：

- 按钮分散在标题区、卡片区、表格区多个位置
- 筛选标签像内容而不是操作控件

### 8.5 卡片类型

后台卡片统一分为三类：

- 信息卡：摘要、说明、状态概览
- 数据卡：表格、列表、批次信息
- 侧栏卡：审核详情、建议、说明

三类卡片共用边框和圆角体系，但密度略有区分。

### 8.6 表单系统

表单页统一为标准后台表单结构。

统一内容包括：

- 标签样式
- 输入框高度
- 文本域样式
- 表单分组标题
- 底部操作栏

目标是让新建商品、编辑商品、分类管理、横幅管理这些页具备一致的“后台录入系统感”。

### 8.7 状态标签

状态标签统一颜色与语义映射：

- 来源类：自动抓取、手动导入
- 审核类：待审核、可发布、已发布
- 任务类：正常、需修复、运行中
- 通知类：待发送、失败待重发、已完成
- 分析类：已生成

状态标签是后台工作流的重要视觉语言，必须保持统一。

## 9. 页面范围与实施边界

### 9.1 本次覆盖页面

本次 UI 美化覆盖以下核心页面：

- 商品中心
- 抓取任务
- 订阅与通知
- AI 数据分析
- 分类管理
- 横幅管理
- 留言管理
- 新建商品
- 编辑商品

### 9.2 本次重点顺序

推荐实施顺序如下：

1. 后台公共壳层
2. 商品中心
3. 抓取任务
4. 订阅与通知
5. AI 数据分析
6. 分类、横幅、留言
7. 新建与编辑商品页

这样可以优先保证给用户演示的主路径效果。

### 9.3 明确不做

本轮不涉及：

- 真实抓取逻辑
- 真实邮件发送
- 行为埋点
- AI 分析真实计算
- 后台权限扩展
- 数据模型调整

本轮只做展示层优化和结构统一。

## 11. 验收标准

当以下条件成立时，本轮设计视为达标：

- 后台页面顶部不再呈现割裂状态
- 页面标题区、摘要区、内容区具有统一秩序
- 核心 demo 页面具有明显更强的首屏表达
- 表格、表单、卡片和 badge 看起来属于同一系统
- 页面足以作为客户静态确认的演示稿，而不是开发占位页

## 12. 后续实现建议

确认本设计后，下一步实现建议按以下顺序推进：

1. 先收口后台公共壳层和标题系统
2. 再统一四个核心 demo 页面
3. 最后补齐配置页和表单页的风格一致性

这样能够以最小风险快速提升演示质量。
